# Changelog

## 1.3.0

- Fence working store and archive writes with the same lock. Validate archive generations and protect local accounting and backup files with private permissions.
- Verify JSONL prefixes before incremental reads. Strict CLI flushes accept complete final lines without a newline, report damaged or ambiguous usage and show collection status by source.
- Repair UTC attribution for copied Claude messages, Codex compatibility and fork reconciliation, Antigravity zero corrections and model fallback, and DSH revisions that omit a known route.
- Preserve known costs when some token types have no price. Use exact reference models and recognized aliases, support source and provider overrides, and consolidate fixed-rate CSV rows.
- Add the optional **Configure Rates** action and independent collection switches. Use the effective setting scope when editing a budget or display zone.
- Reuse verified ledger snapshots for unchanged polls and render one page of sessions. Coalesce detail reads, preserve keyboard focus and improve budget and narrow-panel accessibility.
- Keep collecting after an unreadable log line. In the extension a line that cannot be parsed or fails validation is skipped and the cursor moves past it. The problem names the file, byte offset and reason, is shown again on every poll for as long as the file carries that line, and keeps the source Incomplete. A line over 32 MiB is skipped without being buffered. The strict CLI flush still fails with exit status 1 on any unreadable line.
- Validate every record before it is counted. A timestamp outside 1970-01-01 to 9999-12-31 is an invalid timestamp instead of a malformed day or an extra month, and Claude Code entries whose usage has no token fields (for example only `server_tool_use`) are ignored.
- Follow symlinked folders and log files under the Claude Code, Codex and Antigravity roots, with loop protection. A dangling link counts as a vanished file; a loop or a permission failure is reported as a problem. DSH discovery keeps its containment rules.
- Read DSH logs that contain U+2028, U+2029, U+0085 or CRLF inside JSON strings. A DSH log with a content problem that cannot change is remembered by its fingerprint and reported again without being decoded on every poll; timeouts, worker crashes, files that change during a scan and unsupported generations are still retried.
- Skip an undecodable Antigravity database step with a persistent problem and still collect the valid steps of that database. SQLite work runs in one worker per scan pass instead of one per page, conversation titles are cached until `conversation_summaries.db` changes, and the ten-minute full pass of each database gets a stable offset of up to 20 percent so that databases do not expire together.
- Stop rewriting the ledger for revision-only differences. A newer revision with identical accounting facts is not counted as a change and is saved with the next save, at most 15 minutes later; a real difference, including a downward correction, still persists at once. The ledger no longer stores the redundant `seen` and `open` tables (they are ignored when present, so earlier builds and this one read each other's files), the archive is not read back to decide whether to write it, an invalid `firstDay` is recomputed on load, and cursors of logs that are gone and lie outside every source folder are dropped.
- Make lock recovery explicit and safe against reused process IDs. A lock whose heartbeat is at most 15 seconds old is waited for; one whose owner process on the same host is gone is reclaimed after that; any lock older than 5 minutes is reclaimed whatever its owner, and a lock dated in the future counts by the size of the difference. Writers still check that they own the lock before every save. Temporary files and lock directories older than one hour are swept once per process.
- Keep every command alive while the store is unavailable. Every command, including the legacy aliases, is registered at activation before anything else is initialized. Until the store is ready each command shows one warning with the reason and the buttons Retry, Open Data Folder and Show Log, and the status bar item stays clickable. Initialization retries on the poll interval and recovers by itself after transient failures such as a lock timeout, and the Output channel records a failure only when its text changes. A damaged archive reports the file and points to the README recovery steps; archives are still never moved automatically.
- Apply a settings change made during a poll with one more poll afterwards; the poll timer restarts only when the interval changed.
- Price Claude models from one Anthropic reference table in both Claude Code and Antigravity, so the same model has the same rates in both. Dated ids, `@YYYYMMDD`, `-latest`, `anthropic/`, Bedrock and Vertex spellings and dotted versions resolve to the reference model. Overrides match the logged id and the reference form, exact or with wildcards, and the estimate note says user override when one applies.
- Order results the same on every machine. Ties are broken by code unit instead of the system locale, a session's title and project come from its latest non-empty record, and Claude Code copies with equal timestamps are attributed in code-unit order.
- Make the CLI predictable. `--help`, `-h` and `help` print usage to stdout and exit 0; a missing or unknown command prints usage to stderr and exits 2. The CLI installer removes `dshWorker-<version>.js` files older than the installed CLI.
- Filter Cost per session with a dropdown of check boxes in place of the row of buttons, so any combination of tools can be listed. The button names the choice, All tools clears it, ticking every tool or none is the same as All, and a refresh keeps the menu open. Pages saved by earlier builds start on All tools.
- Remove the JST option from `timeZone`, which now offers `UTC` and `SGT`. A saved `JST` falls back to `SGT`.
- Price the DeepSeek models by default. The DSH default route `deepseek-official` was unpriced; it now bills like `deepseek` and `deepseek-account`, for the flash models (including `deepseek-chat` and `deepseek-reasoner`) and the pro models (`deepseek-pro`, `deepseek-v4-pro`). A DeepSeek model reported by Claude Code, Codex or Antigravity is priced at the same peak rates. Unlisted models and other DSH routes stay unpriced.
- Set the chart text in the typeface of the page: the figure in the By model ring is light like the other figures, the day marked today and the hover amounts are semibold at most, token counts in session cards no longer use the editor's code font, and the status bar chart uses the page's font stack instead of a display face of its own.
- Colour the tools like their model families: Codex in the GPT lavender grey (a softer `#7f79a1` on the light page, a silvery `#b0a9c9` on the dark one) instead of a blue next to DSH's, Claude Code in Claude orange and DSH in DeepSeek blue. The costliest model of a family now wears the family's own colour, so a lone Claude model is Claude orange in the ring and the daily chart instead of a dark brown picked by a hash of its name; the others follow in the order of their names.
- Move the model shares into the Token Usage card and drop the ring card from By model. Under the month's token figure sit the Cost and Tokens switch and the legend of the shares (model, tool, amount, share), with the ring to their right. The centre of the ring is the estimated cost, so the Cost statistic goes (Today, Requests and Conversations stay); the switch also decides which share each model card shows, next to its cost. The ring and its legend show six models before the rest share one slice and one row.
- Redraw the model cards in By model. The model and its cost are the heading, then capsules for the tool, the requests and the share (the share capsule filled to its length in the family colour), then a tile for each of the five kinds of token with its count and the rate that prices it (a dash for a kind the model never used, so every card has the same five), and one line for where the rates come from, whose reference pages are in the hover. The tiles reflow to the width, so the cards hold in a narrow strip.
- Print the rates of a model under the token counts they price, as `$2 $0.1 $2.5 $4 $10` beneath In, Cache read, Cache write, Write 1h and Out, with one line for where they come from (your settings or built in, and the reference). The reference page is in the hover instead of on the card.
- Sort the sessions with one control. The Cost and Recent buttons beside the sort menu are gone; the menu has every order, including those two.
- Make the dashboard controls and counts consistent. Counts of requests have thousands separators everywhere and a single request is "1 request". The sort menu uses the same pill button, rotating caret and floating menu as the tools filter (with a tick on the active order), the month select uses the same thin caret, the pills of the session bar share one height, and every disclosure (cards, log folder, storage details, more models) turns the same small chevron. Previous and Next are pills, the settings link follows the alignment of the lines above it, captions sit under the figures of the overview, token columns line up with the card text on narrow pages, and the ring and its legend are centred in their card.
- Count the conversations of months whose logs are gone. An import of an older ledger carries the per-session totals it kept, not only its day totals, so a month that showed the one conversation a log still held shows the ones the older ledger knew. A session's totals are consumed by what the logs still hold, by session ID, so nothing counts twice, and snapshots of a session merge by the larger count, so a later import refreshes them. The totals are written beside the baseline (`legacySessions`) and not in it, because a build that does not know them rebuilds the baseline on its first transaction and would drop them. The Conversations figure is a floor, shown as `129+` with a hover, when more than 1 percent of the month's requests belong to no session, and its average now divides the sessions' own tokens by their number instead of the whole month's.
- Make the ledger hold Cursor as a fifth tool. Cursor has a name, a colour of its own (the teal of Composer, the family of Cursor's own models), a place in the tools filter, the By tool chart and the CSV, and a card in Collection status that says Imported or No data, since nothing scans it. Its requests are priced from the tables and from your settings, and `import ~/.cursor-usage-monitor/usage.json` brings in the usage ledger of the cursor-usage-monitor extension: one request per event, with ids that stay the same wherever an event sits in the file, so running the import again adds only what is new.
- Read a model by its plain name wherever it runs. The effort and thinking marks a tool adds are dropped for the price lookup and for the page, each maker's own (`-max`, `-high`, `-xhigh`, `-medium`, `-low` and `-thinking` on Claude; `-extra-high`, `-xhigh`, `-high`, `-medium`, `-low` and `-minimal` on GPT and the o-series; `-high`, `-medium`, `-low` and `-minimal` on Gemini), so `gpt-5.1-codex-max` and `kimi-k2-thinking` stay models of their own. Cursor's `claude-4.6-opus` order is turned into Anthropic's `claude-opus-4-6`, and the dotted, dated and prefixed spellings of a Claude model (`claude-opus-4.6`, `claude-sonnet-4-5-20250929`) are the same model, on the page as in the prices; `-fast` stays, as it is priced apart. The ledger keeps the name the tool wrote, and the hover of a card lists the names. Your rate wildcards match the plain name, so `claude-opus-4*` prices Cursor's Opus 4.6.
- Price what Cursor runs. New rows for Cursor's own models (`composer-2.5` and `composer-2.5-fast` at the rates of Cursor's models page; `composer-1`, `composer-2`, `composer-2-fast`, `cursor-auto` and `cursor-agent-review` fitted to a Cursor usage ledger, since the page no longer lists them), GPT-5 to GPT-5.2 and their Codex variants, the GPT-5.5 fast mode at twice the standard rate (the page states none), Gemini 3 Pro and 3.1 Pro, Gemini 3.5 Flash and `gemini-4-argon`. Composer is a model family of its own in the charts. A model the tables do not know stays unpriced and is named in the banner.
- Show a model once, however many tools ran it. A model that ran in Claude Code and in Cursor, or in Antigravity and in Cursor, is one card with a capsule for each tool, one legend row, one slice of the ring and one colour in the daily chart, with the tools named under it in the legend. The rate picker of Configure Rates still lists each tool and each spelling, since a rate can be set for one tool.
- Make the Cost and Tokens switch of the Token Usage card change Daily spend too. In Tokens the card is Daily tokens: the bars, the axis, the peak, the legend and the hover are in tokens by model or by tool, in the colours of the token ring, with the models that have no price that the cost bars leave out. Both drawings are in the page, so the switch needs no message to the extension and the choice survives refreshes. Each drawing has its own focus names and tab stop, the day labels are thinned again when the unit changes, and the even-pace line is drawn in the unit of the budget.
- Fold the legend of the Token Usage card. It shows four rows (five when that is all there is) and the rest sit behind "6 more models", which opens them in place for both the Cost and the Tokens legend and stays as it was across refreshes, so the card stops growing with the number of models.
- Draw the ring thin, with a hair of space between slices, to sit with the hairlines and capsules of the cards. The centre figure is larger, and a slice too narrow for the gap is still drawn as a sliver.
- Show every source in the collapsed Collection status with its state, and call a source whose default data folder is missing Not installed, in the dashboard and in the CLI output (it said Not found). A folder left behind by an uninstalled tool still counts as found.
- Add a ring to By model with each model's share of the month by estimated cost or by tokens, switched with Cost and Tokens. It uses the colours of the daily chart, leaves models without a price out of the cost ring and names them, and folds the models past the eighth into one slice.
- Keep the dashboard steady while it refreshes. Nested diagnostic sections keep their open state and focus, the session popup is not rebuilt when its content is unchanged or while text inside it is selected, and its heading shows the session title when there is one.
- Read the charts more easily. The legend is sorted by cost before it is cut, the per-day hover lists the top models plus an other row and scrolls, model colors stay distinct (DeepSeek shades, GPT against Other in dark themes), the even-pace line follows the active budget metric and mode and disappears when that mode has no budget, usage dated after today is called out instead of stretching the axis, and figures carry at unit boundaries (999,500 reads 1.0M).
- Improve accessibility and harden the dashboard. Chart columns are one tab stop with arrow-key navigation and accessible names, sections are real headings, full titles and exact values are reachable by keyboard, bars, swatches, meters and toggles are drawn in forced-colors mode, and chips have more contrast. The Content Security Policy now also sets `form-action 'none'` and `base-uri 'none'`, and titles, projects, paths, prompts and branches from logs are isolated and stripped of bidirectional control characters.
- Mark the critical budget level with the status bar's error background. After a failed poll the status bar item stays clickable with a matching accessibility label and no longer shows `~$?` in token mode.
- Pair Codex requests one to one. A response that already has its counter no longer takes a later counter of the same turn and usage, a response and a counter whose cumulative totals differ are two requests, and a fork of a fork no longer counts again what the first fork's copy stood for.
- Merge the copies of a Claude message count by count: a streamed update that reports only some counts (for example only a larger output) no longer erases the input and cache counts of the copy that had them.
- Sweep only this extension's own leftovers. The temporary files of the ledger, the archive, the backups, the CLI and its worker, and the displaced lock folders of the ledger and the CLI go once they are over an hour old; every other file of a shared data folder stays.
- Commit every write of the ledger, the archive and the CLI through the lock folder. The new file is staged inside it and renamed from there, so a writer whose lock was reclaimed after its last check fails instead of replacing what the new owner committed.
- Keep Cursor conversations apart on import. Requests with the same millisecond, model and counts but another conversation no longer merge, whichever order the snapshots list them in, and a request imported without its conversation takes it from a later snapshot. No existing id changes.
- Fail a strict flush on usage it recognises but cannot read: a Codex usage record without a payload, and an Antigravity database step that has token counts but no time (a step of zero tokens is still ignored).
- Read DSH around a folder that cannot be listed. The folder is reported and the source stays Incomplete, the other logs are collected, and the state of the logs inside the folder is kept for the next scan.
- Keep the scan report and the collection status when a ledger is imported. A ledger whose scan report is damaged loads without it, and a request time outside 1970 to 9999 is refused like any other malformed request, so neither can fail the dashboard later.
- Keep an older store's tokens that no request stands for in the sessions. A session whose legacy totals were reduced to tokens without requests by what the logs still hold keeps them in its row, its drawer and the month's session total, so the sessions and the unattributed figure add up to the month.
- Say `mixed` on the tile of a model whose tokens of one kind were charged at more than one rate, as when two tools carry different rates of their own or DSH tokens were charged at both its peak and its off-peak rate. The hover lists each rate with the tool, route and tier that paid it and the tokens, and the line under the tiles names both sources when the rates come from your settings and the built-in table.
- Show `est. cost + ?` in the ring when a model is only partly priced, as the status bar and the model cards already did, and say in the note under the legend that its cost is a lower bound.
- Name the ledger file and the archive folder in Storage details, in place of the folder of the Antigravity logs, which stays on its own card.
- Keep All tools ticked when it is clicked while every tool is shown, and let the tool boxes follow the choice at once.
- Print the amounts of Daily spend below a cent with the decimals they need (up to six), so a month of a few hundredths of a cent has distinct axis marks and a peak that is not `$0.00`. Amounts from a cent up print as before.
- Merge the `rates` setting across the user, workspace and workspace-folder settings, as VS Code does for object settings, so a workspace that sets one model's input no longer drops the user's other rates. Configure Rates saves into the scope that already holds the rates and writes only that scope's own entries.
- Verify more before release. The test runner is hermetic (temporary home folder, no data-location variables, no connections beyond the loopback address) and removes stale compiled tests; CI builds before testing, smoke-runs the bundled CLI, checks the VSIX file list and audits production dependencies; the packaged bundles no longer carry a dangling source-map reference; type definitions are pinned to the oldest supported VS Code and Node 18; the package declares its license, Node engine and workspace capabilities. The README is rewritten as reference documentation: release notes live here, the privacy statement lists everything the ledger stores, and skipped lines, locking, the unavailable-store behavior and Node requirements are documented.

- Price Gemini 3.8 Flash (`$0.75`/`$0.075`/`$3.75` introductory rate through 2026-12-31), Gemini 4 Hydrogen (including Antigravity model enum 1525), Gemini 4 Neon and Gemini 4 Carbon in the built-in tables, and strip `-xhigh` effort suffixes on Gemini models.
- Unify the Cost per session dropdowns: the sort selector now uses the same custom pill button, rotating caret and floating menu as the tools filter, with a tick on the active order.
- Add **Export Offline HTML** (`agyTokenTracker.exportOfflineHtml`) to save a self-contained single-file snapshot of all retained months, sessions, details and charts for offline viewing in any browser.
